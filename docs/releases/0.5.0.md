# Baliset 0.5.0

Baliset now plays from your own Jellyfin server too — and keeps the songs you download when the server is not there.

## Connect

**Settings → Server → Jellyfin** (or the server icon on Home) asks for the address, username and password. Baliset finds the server,
signs in, and stores the session token **encrypted with a key in Android's Keystore**. The token is sent only in an `Authorization`
header to that server's host — never in a stream or image URL. A home server is often plain http; the screen says so before signing in,
because the password and what you play can be seen on that network.

Signing out removes the token; downloads stay until you delete them.

## Browse and stream

The Jellyfin screen lists the server's music library by album and by song, with search and artwork. Tapping an album opens its tracks;
**Play** puts the whole album in the queue. Playback is **direct play**: ExoPlayer asks for the original file, using the same
authenticated OkHttp client as the rest of the app, and the media session, notification, lock screen, island, queue, leveling and
crossfade all work as they do locally.

## Download and go offline

**Download** on an album, or the download button on a song, saves the original file to Baliset's own storage with a real progress
percentage. A stopped transfer says why and can be retried; a deleted download removes its file and poster. The **Downloads** tab lists
what is ready, plays it, and deletes it. Downloaded tracks play from the local file even when the server is off; the **Downloads** button
on the sign-in screen gets you there when you are signed out.

Downloads run while Baliset's process is alive. They are not a background download service, so closing the app's process stops one in
progress; the next attempt starts from the beginning.

## What was tried

Against a local mock Jellyfin server (not a real install):

- connect at `10.0.2.2:8099`, sign in, load two albums and four songs, and display the server's artwork;
- stream an album: the server saw `/Audio/{id}/stream` requests, the media session reported PLAYING, and the notification, queue and
  Now Playing page showed the track;
- download a three-track album: the server saw `/Items/{id}/Download` for each, three MP3s and posters landed on the phone, and the
  Downloads tab showed them as downloaded;
- stop the mock server and play a downloaded track: it played from the file, with no server;
- **79 JVM tests** pass, including the Jellyfin API, URL building and the item-to-track mapping.

## Limits

- **No transcoding.** Baliset asks for the original file. A codec Android cannot decode will not play; there is no server-side
  transcode fallback yet.
- Downloads are app-process work, not a background service; closing the process stops an in-progress transfer.
- Only the first music library on a server is shown.
- A real Jellyfin server was not available here; the mock follows Jellyfin's API but a real server may differ in edge cases.
- Cleartext http is allowed so a server at home works; the sign-in screen warns when the address is not https.

## Installing

Sideload the APK. It is signed with the same key as 0.4.1, so it installs over it and keeps the library, playlists, settings, artwork,
loudness measurements and downloads.
