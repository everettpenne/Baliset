# Baliset 0.4.1

Two things: the covers come back, and the library gets a check-up.

## The album art is back

0.4.0 changed how an album is identified so that guest credits would stay on one album. The artwork cache was keyed by that identity,
so after a rescan every album went looking for a cover under a new name, and the covers already on the phone were orphaned.

0.4.1 repairs that:

- when an album has no cover under its current key, **the old cached cover is adopted** — including one downloaded from MusicBrainz,
  which has no embedded art to re-read;
- if there is no old file, Baliset **re-reads the folder image, the embedded art, the AIFF ID3 picture or Android's thumbnail**;
- the repair runs **on launch and during every scan**, and it **tries every track in the album**, not just the first, so a guest track
  without art no longer hides a cover that a later track has;
- **Settings → Library check → Re-read local covers** forces the repair;
- a zero-byte cover file no longer counts as a cover.

No rescan is required for the covers, but one is still recommended after 0.4.0 so the album grouping is recalculated.

## Library check

**Settings → Library check** runs a read-only audit:

- **missing files** — a folder document or file that has gone;
- **unplayable formats** — WMA, APE, MPC, DSD, WavPack, TTA, FairPlay `.m4p`, and AIFF files with compression Android cannot decode;
- **duplicate groups** — same title, artist and length (it only reports; nothing is deleted);
- **albums without a cover** — with **Find missing covers** (MusicBrainz, opt-in) and **Re-read local covers**;
- **tracks without tags** — those falling back to a file name;
- **zero-length tracks**.

Everything is local and read-only. The one network action is the MusicBrainz cover lookup, and only when the switch is on and the
button is pressed.

## What was tried

- A deliberately wrong old cover (a red square) was placed under the pre-0.4 album key and the current cover deleted. On restart the red
  cover was adopted and displayed for The Cure.
- The LMFAO cover was deleted at both its old and new keys; on restart it was re-read from the MP3's own embedded art.
- The library check on the test library reported the two albums that really have no cover (the synthetic *Isolation* and *Two Discs*
  folders) and no false missing files, format problems, duplicates or zero-length tracks.
- **59 JVM tests** pass, including a test for the old/new art key list.

## Limits

- The repair can only restore art that still exists somewhere: an old cached file, a folder image, embedded art, or an AIFF picture.
  An album whose source truly has no cover is reported by the check and can be given one with MusicBrainz.
- The health check reads each saved file's existence and AIFF header; on a very large library it takes a little while, with progress.
- Crossfade and audio focus remain emulator-tested, as in 0.4.0.

## Installing

Sideload the APK. It is signed with the same key as 0.4.0, so it installs over it and keeps the library, playlists, settings, loudness
measurements and — after the repair — the artwork.
